## 산출물 ① — 네트워크: 2건, **탭과 무관하게 둘 다 나간다**

```
1. GET /api/v1/trainers/reservation/new?memberId=6                      → 200
2. GET /api/v1/trainers/reservation/old?searchDate=2026-09&memberId=6   → 200
```

서베이의 추론과 **일치**한다(이번엔 맞았다). 훅이 페이지 컴포넌트에 있어
Radix Tabs가 비활성 `TabsContent`를 언마운트해도 둘 다 발사된다.

- **하단바가 없다**(`hasNav: false`) — `<Layout>`에 `type`이 없다. S4와 다른
  점이고, 그래서 `trainer-mapping` 같은 네비 요청이 붙지 않는다.
- 골든: `har/trainer-manage-reservation.har` → `test/fixtures/requests/trainer-manage-reservation.json`.

### 월 변경 시

`old`만 새 `searchDate`로 다시 나간다. `new`는 다시 나가지 않는다.

```json
{"scheduleId":984,"lessonDt":"2026-04-13","lessonStartTime":"04:00:00",
```

### 확정된 것

| 항목 | 실측 결과 |
|---|---|
| **빈 목록** | **`reservations: null`이다. `[]`가 아니다.** S3·S4의 페이징 응답(`content: []`)과 **반대**다 — 같은 백엔드인데 엔드포인트마다 다르다 |
| **`/old`의 `course`** | **항상 `null`**이다(계약 ⑦ 그대로). `/new`만 채워 준다 |

| `reservationStatus` | 영어 문자열(`COMPLETED` 등). 웹이 `=== 'COMPLETED'`로 비교한다 |

## 산출물 ④ — 새 웹 버그: `twSelector`가 만든 클래스는 **생성되지 않는다**

활성 탭이 `HEADING_5`(600)여야 하는데 **실측이 400**이다. 원인:

```ts
// shared/utils/tw-utils.ts
export const twSelector = (pseudo, target) =>
  target.split(' ').map((str) => `${pseudo}:${str}`).join(' ');
```

`twSelector('data-[state=active]', Typography.HEADING_5)`는 **런타임에**
`data-[state=active]:text-[13px]/[150%] data-[state=active]:font-semibold`를
조립한다. Tailwind JIT은 **소스 파일에서 완성된 클래스 문자열을 스캔**하므로
이 문자열들을 본 적이 없고, 따라서 **CSS를 생성하지 않는다.**

같은 트리거의 `data-[state=active]:bg-primary-500 data-[state=active]:text-white`는
**소스에 리터럴로 적혀 있어서** 정상 동작한다(실측: 배경·글자색은 바뀐다).
**한 버튼 안에서 리터럴은 먹고 런타임 조립은 안 먹는 것이 이 버그의 증거다.**

### 영향 범위

`twSelector`는 9개 파일에서 쓰인다. 나머지 8곳은 전부
`twSelector('placeholder', Typography.BODY_1)` 형태인데, **입력 자체에 이미 같은
타이포가 걸려 있어 placeholder가 그것을 상속하므로 시각적 차이가 없다.**
실제로 드러나는 곳은 **S5의 활성 탭 굵기 하나**다.

> **BUG-14(S4)와 짝을 이루는 사례다.** 거기서는 "클래스가 생성되지 않는다"는
> 서베이의 주장이 **틀렸고**(extend라 기본값이 살아 있었다), 여기서는
> **실제로 생성되지 않는다**(런타임 조립이라 스캔이 안 된다).
> **둘 다 실측으로만 갈렸다.**
